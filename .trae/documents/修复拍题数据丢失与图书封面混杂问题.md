# 修复“拍题”数据丢失与图书封面混杂问题

## 1. 问题诊断
- **显示异常原因**：后端 `fileStorage.ts` 中的 `queryMetadata` 函数硬编码为仅查询 `books` 表。这导致“拍题”页面（请求 `/api/scanned-items`）获取到了图书数据，而忽略了真正的拍题识别数据。
- **数据丢失风险**：虽然 `deploy.sh` 脚本本身不删除数据，但如果后端服务在 Docker 容器中运行且未挂载持久化卷（Volume），重新部署会导致容器内的 SQLite 数据库和文件丢失。

## 2. 技术实施方案

### A. 后端逻辑修正 (核心修复)
1. **修改 `fileStorage.ts`**：
   - 重构 `queryMetadata` 函数，增加对 `scanned_items` 表的支持。
   - 根据传入的 `type` 参数自动选择查询表：若 `type === 'textbook'` 查询 `books` 表；否则查询 `scanned_items` 表。
   - 确保 `scanned_items` 查询逻辑包含 `allImagesJson` 和 `problemsJson` 等特有字段。

2. **更新路由调用**：
   - 检查 [scannedItems.ts](file:///d:/devops/HL-os/backend/src/routes/scannedItems.ts)，确保查询时能正确获取拍题数据。
   - 检查 [books.ts](file:///d:/devops/HL-os/backend/src/routes/books.ts)，确保其仅获取图书数据。

### B. 部署脚本优化
- **增加持久化提示**：在 [deploy.sh](file:///d:/devops/HL-os/deploy.sh) 中增加检查，确保 `/opt/hl-os/data` 目录的持久化属性，并建议用户备份 `hlos.db`。

## 3. 验证方案
1. **分类验证**：上传一张试卷照片，确认其仅出现在“拍题”档案库中。
2. **隔离验证**：上传一本图书，确认其封面仅出现在“图书馆”中，不会混入“拍题”页面。
3. **重启验证**：模拟重启后端服务，确认识别后的数据依然存在（排除数据库丢失问题）。

## 4. 关键代码变动位置
- [fileStorage.ts](file:///d:/devops/HL-os/backend/src/services/fileStorage.ts): `queryMetadata` 函数。
- [scannedItems.ts](file:///d:/devops/HL-os/backend/src/routes/scannedItems.ts): API 调用逻辑。
- [books.ts](file:///d:/devops/HL-os/backend/src/routes/books.ts): API 调用逻辑。
