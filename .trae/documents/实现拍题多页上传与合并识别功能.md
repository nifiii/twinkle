# 实现拍题多页上传与合并识别及规范化存储功能

## 核心需求分析
1. **多图上传限制**：前端严格限制单次上传不超过 4 张图片。
2. **多图合并识别**：前端串行识别多张图片，识别完成后将所有内容的 Markdown 和题目列表（Problems）合并为一份完整试卷。
3. **Markdown 格式规范**：后端存储时确保 Markdown 格式标准，包括正确的换行、标题层级和数学公式 LaTeX 格式。
4. **全流程持久化与溯源**：
   - **原始图片**：按 `originals/Exams_Homework/日期/科目/学生/` 路径保存。
   - **主 Markdown**：按 `obsidian/Exams_Homework/日期/科目/学生/` 路径保存。
   - **错题 Markdown**：按 `obsidian/Wrong_Problems/日期/科目/学生/` 路径保存，并剥离为原子化文件。
   - **数据库索引**：SQLite (`scanned_items` 表) 必须完整记录 `imagePath` (原始图)、`mdPath` (主 MD) 和 `problemsJson` (结构化数据)。

## 技术实现方案

### 1. 前端逻辑升级 (CaptureModule.tsx)
- **上传校验**：在 `handleFileChange` 中增加检查，若 `files.length > 4`，弹出 Toast 警告并清空选择。
- **批量合并逻辑**：
  - 引入 `batchResults` 数组暂存每页识别结果。
  - 在 `processSerially` 流程中：
    - 每张图片识别成功后，将其结果 push 到 `batchResults`。
    - 当所有图片处理完毕，触发 `mergeBatchResults` 函数。
  - **合并算法 `mergeBatchResults`**：
    - **Raw Markdown**：使用 `\n\n---\n\n**第 {n} 页**\n\n` 作为分页符拼接所有页面的 Markdown。
    - **Problems**：将所有页面的 `problems` 数组扁平化合并，重新生成 `questionNumber`（如需连续编号）。
    - **Meta**：以第一页的元数据（学科、类型）为主，若后续页面有不同学科（罕见）则保留第一页为准。
    - **Image URL**：`reviewItem` 的预览图默认展示第一张，但在保存时需将**所有原始图片**上传。
    - **多图保存逻辑**：由于目前后端接口是单图设计，需改造前端 `handleSaveAndArchive`，将所有图片 Base64 数组传给后端（需后端接口配合修改）。**或者**（简化方案）：仅保存第一页作为封面，或者将多图合成 PDF（成本高）。
    - **优选方案**：前端将多张图片 Base64 封装在 `originalImages` 数组中一次性发给后端。

### 2. 后端接口升级 (saveScannedItem.ts & fileStorage.ts)
- **接口定义变更**：
  - `saveScannedItem` 路由接收 `originalImagesBase64: string[]` (数组) 而非单张 `originalImageBase64`。
  - 兼容旧版单图请求（将单图转为数组）。
- **图片存储逻辑 (`saveOriginalImage`)**：
  - 循环处理图片数组，生成多个文件路径。
  - 返回 `imagePaths: string[]`。
  - 在 SQLite 和 Markdown 中，`imagePath` 字段存储为逗号分隔的字符串或 JSON 数组，或者仅存第一张作为主图（视 Obsidian 预览需求定，建议存第一张为主，正文中插入所有图片链接）。
- **Markdown 生成逻辑 (`generateObsidianMarkdown`)**：
  - 在 Markdown 正文顶部插入所有原始图片的引用：`![[image1.jpg]] ![[image2.jpg]] ...`。
  - 确保内容部分使用标准 Markdown 换行（`\n\n`）。

### 3. 数据库与存储规范
- **SQLite (`scanned_items`)**：
  - `imagePath`: 存储第一张图片的路径（用于封面展示）。
  - `problemsJson`: 存储合并后的完整题目结构。
  - 确保 `userName` 和 `subject` 字段正确写入，用于后续目录索引。
- **错题归档 (`generateWrongProblemMarkdown`)**：
  - 保持现有逻辑，将错题单独存为 `.md` 文件。
  - 错题文件中引用原始图片时，尽量引用该题目所在的那一页图片（这需要前端传递题目与页码的对应关系）。**简化策略**：错题文件引用第一张主图，或者引用所有原图。

## 验证计划
1. **多图限制**：尝试上传 5 张图，确认被拦截。
2. **合并显示**：上传 2 张试卷，确认校对界面能看到两页的所有题目，且 Markdown 预览中包含分页符。
3. **持久化检查**：
   - 检查服务器 `originals/...` 目录下是否有 2 张图片。
   - 检查 `obsidian/...` 下的主 Markdown 文件是否引用了这 2 张图片。
   - 检查 SQLite 数据库中 `scanned_items` 记录是否完整。
4. **错题库**：检查 `Wrong_Problems` 目录下是否生成了对应的错题文件。
