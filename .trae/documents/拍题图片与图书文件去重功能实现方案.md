# 拍题图片与图书文件前置去重功能实现方案

为了最大化提升用户体验并节省带宽，我们将在**浏览器端（前端）**优先计算文件哈希值，并在文件真正开始上传前与服务器进行比对，从而实现精准拦截。

## 1. 数据库层级升级
*   **字段扩展**：修改 [databaseService.ts](file:///d:/devops/HL-os/backend/src/services/databaseService.ts)，为 `books` 和 `scanned_items` 表新增 `fileHash` 字段（TEXT类型）。
*   **自动迁移**：在 `initDatabase` 中加入检测逻辑，确保现有数据库在系统启动时自动完成字段添加。

## 2. 后端：哈希校验 API
*   **新建路由**：创建 `backend/src/routes/files.ts`，提供 `GET /api/files/check-hash/:hash` 接口。
*   **多表检索**：该接口将同时检索书籍库和扫描记录库，若发现匹配，返回该文件的详细信息（如书名或上传日期），以便前端展示。
*   **存储持久化**：更新 [fileStorage.ts](file:///d:/devops/HL-os/backend/src/services/fileStorage.ts)，确保在最终保存元数据时将哈希值存入数据库。

## 3. 前端：前置哈希计算
*   **高效计算**：利用浏览器原生 `crypto.subtle` API（SHA-256 算法）实现高性能哈希计算，无需上传即可获取指纹。
*   **图书流程集成**：
    *   在 [BookUploader.tsx](file:///d:/devops/HL-os/components/BookUploader.tsx) 中，用户选择文件后立即触发计算。
    *   在分片上传启动前，先调用校验接口。若文件已存在，直接拦截并提示用户。
*   **图片流程集成**：
    *   在 [CaptureModule.tsx](file:///d:/devops/HL-os/components/CaptureModule.tsx) 中，对捕获的 base64 图片或选择的相册图片进行哈希计算。
    *   在提交 AI 分析或保存前进行校验，防止重复扫描同一份作业。

## 4. 交互反馈优化
*   **智能提示**：当检测到重复时，弹窗提示：“该文件已上传过（上传于 YYYY-MM-DD）”。
*   **容错处理**：如果哈希校验失败（网络波动等），默认允许上传，由后端在最后保存阶段进行兜底校验。

## 5. 实施步骤
1.  **第一阶段**：后端数据库迁移及哈希校验接口开发。
2.  **第二阶段**：前端哈希计算工具函数开发。
3.  **第三阶段**：在图书上传组件中植入前置拦截逻辑。
4.  **第四阶段**：在拍题/扫描组件中植入前置拦截逻辑。
