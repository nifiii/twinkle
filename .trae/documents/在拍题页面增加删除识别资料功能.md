# 在“拍题”页面增加删除功能

## 1. 核心改进目标
*   **物理删除**：删除 SQLite 数据库记录的同时，彻底删除磁盘上对应的原始图片和生成的 Markdown 文件。
*   **安全确认**：在执行删除操作前，向用户弹出二次确认对话框，防止误操作。
*   **状态同步**：删除成功后，前端页面立即刷新，移除已删除的项目。

## 2. 技术实施方案

### 第一步：后端功能增强 (fileStorage.ts & scannedItems.ts)
*   **fileStorage.ts**: 
    *   重构 `deleteMetadata(id)` 函数。
    *   逻辑：先根据 ID 查询出 `mdPath`, `imagePath` 和 `allImagesJson`。
    *   物理删除：将磁盘上的对应文件全部删除（需处理相对路径到绝对路径的转换）。
    *   数据库删除：从 `scanned_items` 表和 `books` 表（如存在）中移除记录。
*   **scannedItems.ts**: 
    *   新增 `DELETE /api/scanned-items/:id` 路由，调用上述删除函数。

### 第二步：前端 API 与组件更新 (apiService.ts & App.tsx)
*   **apiService.ts**: 
    *   新增 `deleteScannedItem(id)` 函数，封装对后端删除接口的调用。
*   **App.tsx**: 
    *   实现 `handleDeleteScannedItem(id)` 回调函数，负责调用 API 并更新本地 `scannedItems` 状态。
    *   将该函数透传给 `CaptureModule`。

### 第三步：UI 交互重构 (KnowledgeHub.tsx)
*   **组件透传**：在 `KnowledgeHub` 中接收 `onDelete` 回调。
*   **添加删除按钮**：
    *   在“平铺视图”的卡片右上角增加一个红色垃圾桶图标。
    *   在“卷宗模式”的列表项右侧增加删除操作。
*   **二次确认逻辑**：
    *   点击删除时，调用 `window.confirm` 或实现一个简易的确认 Modal。
    *   确认后触发删除流程，并展示加载状态。

## 3. 验证方案
*   **数据库验证**：删除一个条目后，使用 SQLite 工具或 API 验证记录已消失。
*   **文件系统验证**：进入 `/opt/hl-os/data/obsidian` 和 `/opt/hl-os/data/originals` 目录，确认对应的 `.md` 和 `.jpg` 文件已被物理删除。
*   **交互验证**：验证点击“取消”不会删除数据，验证删除后列表实时更新。
