# 性能优化 UI/UX 设计契约

状态：Gate 3 已确认

## 1. 背景

本次工作新增的是异步任务与实时会话的状态表达，不是重新设计学习产品的视觉品牌。

## 2. 目标

在保持 React、Tailwind 和既有组件风格的前提下，提供易扫描、可恢复、移动端可用的任务状态界面。

## 3. 方案

### 产品与视觉方向

- 产品类型：家庭学习应用。
- 使用方式：学生与家长的重复日常操作。
- 视觉方向：保留既有轻量学习风格；任务状态采用克制、信息优先的操作型表达。
- 资产：沿用 Lucide 图标和现有视觉资源；不新增装饰性图片。

### 组件规则

| 组件 | 规则 |
| --- | --- |
| 任务状态行 | 固定高度，包含状态图标、阶段名、已耗时、重试命令；不使用无限旋转加载遮挡全部内容。 |
| 队列提示 | 只展示真实队列状态与等待时长；无可靠位置时不展示虚假序号。 |
| 进度条 | 仅用于可量化上传字节；模型处理使用状态文本。 |
| 重试 | 使用清晰命令按钮；仅对失败或未完成阶段可用。 |
| LiveTutor | 麦克风、连接、播放和错误状态以图标加文本共同表达；不只依赖颜色。 |

### 交互与可访问性

- 所有重试、关闭和重新连接按钮可通过键盘聚焦与触发。
- 状态变化使用 `aria-live` 区域，避免依赖动画传递关键信息。
- 错误信息必须说明可重试性，不暴露 API Key、内部路径或上游原始响应。
- 移动端任务状态内容纵向排列，长错误文本换行，按钮不挤压文本。

### 响应式与动效

- 桌面端在上传器、拍题和课件生成器内展示完整状态行。
- 移动端保留阶段、耗时和操作，隐藏仅用于诊断的次级字段。
- 动效仅表示连接、上传或音频播放，不延迟可点击操作；遵从减少动效偏好。

## 4. 风险

- 将技术阶段直接暴露给儿童用户可能增加认知负担，因此状态名称必须面向用户，而详细诊断保留给运维日志。
- 过度频繁刷新状态会制造网络负载，前端轮询策略必须由 Gate 4 的任务契约约束。

## 5. 回滚

任务 UI 是增量状态展示；发生问题时可隐藏新状态组件并继续显示已有加载与错误提示。

## 6. FAQ

### 是否需要重做页面？

不需要。本次只增加任务状态、重试与 LiveTutor 会话反馈，不改变顶级导航和学习内容布局。
