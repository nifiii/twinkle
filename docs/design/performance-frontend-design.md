# 性能优化前端实现契约

状态：Gate 3 已确认

## 1. 背景

现有前端分别在 `BookUploader`、`CaptureModule`、`CoursewareGenerator` 和 `LiveTutor` 管理长任务状态，缺少统一的服务端任务恢复与队列表达。

## 2. 目标

建立前端状态边界，使所有资源密集任务通过同一种任务查询和展示模式工作，且 LiveTutor 不再在浏览器持有供应商密钥。

## 3. 方案

### 路由与页面组成

| 页面/组件 | 责任 |
| --- | --- |
| `BookUploader` 与书架卡片 | 提交图书任务、展示上传和后台处理状态、恢复未完成图书。 |
| `CaptureModule` | 提交 OCR-only 和结构化分析任务、展示两阶段结果与重试。 |
| `CoursewareGenerator`、错题课件入口 | 提交课件任务、展示排队/生成/保存状态。 |
| `LiveTutor` | 采集与播放 PCM、展示会话状态；只连接本服务的实时会话入口。 |

### 状态管理边界

- 前端持有展示状态和短期轮询控制；任务真相、阶段时间、队列状态与可恢复结果由后端持久化。
- 所有任务响应必须提供稳定任务标识；页面刷新后根据标识恢复状态。
- 轮询只在排队或运行中进行；进入终态立即停止；网络抖动采用有限重试。
- 前端不得以 `setTimeout` 伪造阶段完成，也不得保存或读取任何 Gemini 密钥。

### API 使用边界

- 任务提交、状态查询、重试与结果读取使用统一任务语义；具体 REST/WebSocket 字段由 Gate 4 固定。
- LiveTutor 使用浏览器到本服务的认证会话，后端代理豆包实时音频；浏览器仅发送必要音频帧和接收音频/转写事件。

### 前端非目标

- 不在浏览器端进行 PDF 解析、全本 OCR 或模型输出拼接。
- 不把队列或任务状态仅保存在 React state。

## 4. 风险

- 现有 `services/geminiService.ts` 实际多为 API 包装，重命名时必须同步全部导入，避免留下误导性 Gemini 命名。
- WebSocket 断线和页面后台挂起会影响 LiveTutor，必须处理本地 AudioContext、麦克风流和重连状态。

## 5. 回滚

前端使用版本化任务接口。若新接口不可用，运行时开关回退到当前流程；旧页面仍能读取旧任务记录。

## 6. FAQ

### 为什么 LiveTutor 要改为服务端代理？

浏览器直连会暴露供应商密钥，也无法统一控制会话鉴权、限流、审计和服务切换。
