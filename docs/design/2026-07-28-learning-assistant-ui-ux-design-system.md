# 学习小助手重构：UI/UX 视觉与版面契约（Gate 3）

状态：已确认（Gate 3）

依据：`2026-07-28-learning-assistant-frontend-design.md`、BR-001 至 BR-020。

## 1. 背景

现有页面混用深色赛博背景、渐变标题、大圆角容器和白底学习页。学生需要快速识别“我现在该选什么”和“生成后在哪里继续”，视觉不应抢夺教材、错题和试题的注意力。

## 2. 目标

为小学高年级至青少年提供一个明亮、直接、重复使用友好的学习工作台：学生看见页面后能立即区分错题流与教材流，清楚知道下一步和任务状态；家长查看时能快速定位范围、结果与复核入口。

## 3. 方案

### 3.1 产品类别与视觉方向

| 项目 | 决策 |
| --- | --- |
| 产品类别 | 家庭学习工具，日常高频任务工作台。 |
| 视觉方向 | 明亮的“学习桌面”：纸白内容面、石墨文字、克制的绿色主操作、清晰的蓝色信息、琥珀色提示。 |
| 密度 | 中等偏高。优先连续阅读与多次操作，不做营销式大幅 Hero。 |
| 情绪 | 有活力但不幼态；颜色用于学科与状态，不用装饰性渐变或漂浮光斑。 |
| 内容资产 | 教材选择和任务行可使用已上传教材封面缩略图；缺失时使用学科 Lucide 图标。绝不展示无关库存图片。 |

### 3.2 设计令牌

| 类别 | Token | 值/规则 |
| --- | --- | --- |
| 页面背景 | `canvas` | `#F7F8F5`，无渐变。 |
| 主内容面 | `surface` | `#FFFFFF`，仅表单、抽屉、任务行悬浮态使用。 |
| 主要文字 | `ink` | `#1F2933`。 |
| 次要文字 | `muted` | `#5D6B78`。 |
| 分隔线 | `border` | `#D9E1E7`。 |
| 主操作 | `primary` | `#16803D`；hover `#106B32`；焦点环 `#69C68B`。 |
| 信息/链接 | `info` | `#1D6FB8`。 |
| 提示 | `warning` | `#B96A00`，搭配浅底 `#FFF4D8`。 |
| 错误 | `danger` | `#C43B32`，搭配浅底 `#FDE8E6`。 |
| 成功 | `success` | `#16803D`，搭配浅底 `#E8F6EC`。 |
| 学科色 | 数学/英语/语文/科学 | `#2563B8` / `#9B3E8C` / `#B45309` / `#087A73`；仅用于标签、图标和细节。 |
| 字体 | `body` | 随镜像发布的 SIL OFL 1.1 `Noto Sans CJK SC`，系统无衬线回退。 |
| 字号 | 正文/说明/页标题 | 16px / 14px / 24px；不以视口缩放字号。 |
| 间距 | `space-1..8` | 4, 8, 12, 16, 24, 32, 40, 48px。 |
| 圆角 | 控件/内容面/模态 | 6px / 8px / 8px；不使用胶囊式大圆角卡片。 |
| 阴影 | 浮层 | 仅抽屉、菜单、固定行动条使用 `0 8px 24px rgba(31,41,51,.12)`。 |

### 3.3 全局版面

- 桌面侧栏宽度 248px，顶部栏高度 64px，主内容最大宽度 1200px。
- 全局导航顺序固定：我的看板、学习资料、学习小助手、智慧课堂。当前项目在图标旁使用完整中文标签。
- 移动端底栏为四等分；`学习小助手` 标签可以两行显示，不能截断为省略号。
- 主内容使用全宽带状区域和内部 1200px 容器，不把整页包进浮动卡片。
- 页面标题位于内容首行，右侧只保留当前学生切换与必要状态，不额外放营销说明。

### 3.4 学习小助手版面

```text
标题行：学习小助手                     当前学生
来源切换：错题讲解与测验 | 教材章节学习
--------------------------------------------------
主区（桌面 8 列）                         选择摘要（4 列）
错题列表 / 教材与章节选择 / 学科动作         已选范围、知识点、生成说明
--------------------------------------------------
固定行动条：选择状态                       主按钮
```

- 来源切换为带图标的分段控件，而不是两张竞争性大卡。活动项使用实心底色和底部 2px 指示线。
- 错题以可勾选的分隔列表呈现，每行左侧真实复选框，中部题目和知识点，右侧来源与状态。行高至少 72px。
- 教材选择用封面缩略图加两级字段：教材选择、章节选择。章节选择打开目录抽屉；确认后显示可编辑摘要，避免长目录常驻占空间。
- 学科动作使用等高图标加文本块，桌面 3 列、平板 2 列、手机 1 列。只有明确命令为按钮，状态信息不是按钮。
- 不可用动作保持占位并给出原因，例如“需先选择章节”“无可嵌入视频”“缺少匹配年级的奥数资料”；不通过仅降低透明度隐藏语义。
- 固定行动条只在存在可执行选择时出现。主按钮显示动词和产物，例如“生成讲解与测验”，不能写“开始”。

### 3.5 智慧课堂版面

```text
标题行：智慧课堂                         当前学生
继续学习：横向 1 至 3 条紧凑任务行
筛选：状态 | 学科 | 类型 | 教材/章节
--------------------------------------------------
任务列表：类型图标 + 标题/来源 + 状态/时间 + 一个主操作
```

- “继续学习”最多三条，超出不横向堆叠；使用“查看全部任务”文字链接进入筛选后的列表。
- 全部任务为分隔列表，不在卡片里再嵌套卡片。标题可换两行，教材/章节和时间为次级行。
- 类型图标固定且一一对应：书本课件、清单随堂测验、耳机听力、播放视频、脑图思维训练、试卷模拟考试、警示符错题讲解与测验。
- 状态标签带文本和图标。主操作是右对齐文本按钮，移动端移到行尾下一行，不覆盖标题。
- 删除、重新生成、复核等低频或高风险操作放入“更多”图标菜单，带 tooltip 和确认对话框。

### 3.6 控件与交互规范

| 控件 | 规则 |
| --- | --- |
| 主按钮 | 绿色实底、最小 44px 高；生成中使用加载图标并禁用重复提交。 |
| 次按钮 | 白底描边；仅用于返回、重新选择、查看范围。 |
| 图标按钮 | 只用于更多、关闭、返回、刷新等熟悉动作；均有 tooltip 与可访问名称。 |
| 选择字段 | 始终显示标签；教材和章节使用可检索选择/目录抽屉，不以 placeholder 代替标签。 |
| 标签/筛选 | 状态、学科、类型使用可组合筛选 chip；chip 不是主操作，支持键盘切换和清除。 |
| 任务进度 | 用文本、图标和确定/不确定进度条组合表达；不得只转圈且没有说明。 |
| 校验 | 在字段下立即说明原因；提交后将焦点移到首个无效字段。 |
| 成功反馈 | Toast 简短确认，并在行动条提供进入智慧课堂的按钮；不自动跳转打断学生。 |
| 失败反馈 | 原选择不丢失；显示可操作重试，模型/资源错误不泄露敏感服务信息。 |

### 3.7 可访问性与动效

- 正文和交互文字对比度至少 4.5:1；学科色不是唯一信息载体。
- 触控目标至少 44 x 44px；复选框行整体可点击但不妨碍键盘独立聚焦。
- 焦点环为 2px `primary` 外环，绝不去除 outline 且无替代。
- 所有抽屉、菜单和对话框支持 Esc 关闭并将焦点归还触发元素；交卷确认除外。
- 尊重 `prefers-reduced-motion`；默认动效只使用 150 至 200ms 的淡入或状态过渡，不做漂浮、弹跳、视差或循环装饰动画。

### 3.8 响应式细则

| 视口 | 规则 |
| --- | --- |
| 390px | 单列；来源/筛选横向滚动；行动条固定在底栏安全区上方；长教材名和章节名换行；任务操作落到独立行。 |
| 768px | 教材字段两列，动作两列；课堂筛选多行但保持筛选顺序。 |
| 1024px 及以上 | 助手主区 8 列 + 摘要 4 列；课堂任务列表使用 4 列信息布局，但标题列最小 320px。 |

### 3.9 视觉验收

- 在 390px、768px、1440px 截图中，导航、标题、行动条、长文本和底栏没有遮挡或截断。
- 错题、教材、视频资源空、生成中、生成失败、任务完成六种状态均检查颜色以外的文本与图标提示。
- 键盘从页头到生成按钮、从课堂筛选到任务主操作可连续到达；焦点可见。
- 检查教材封面缺失时的学科图标回退；不出现失效图片占位或装饰图。

## 4. 风险

将现有深色赛博外壳直接和明亮学习工作台拼接会造成视觉断裂。实施时应优先将全局 Layout、学习小助手和智慧课堂一并切换到同一令牌，而不是只给单页换肤。

## 5. 回滚

视觉令牌和组件样式应使用局部主题变量与稳定组件类，不改变任务、教材、试卷和课堂 API。出现可读性回归时可恢复旧主题变量，业务路由与数据不变。

## 6. FAQ

### 为什么不继续使用大面积渐变和发光？

学生需要长时间阅读教材、题目和评分反馈。高对比文字、稳定层级和有限的状态色更容易扫描，也不会掩盖“当前可操作/不可操作”的差异。
