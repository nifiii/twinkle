## 1. 产品概述

### 1.1 定位

**闪闪** 是一个面向 K12 家庭的自主把控教材学习 AI 小助手。利用火山引擎豆包多模态大模型，将纸质学习资料（教材、试卷、作业）数字化，并生成个性化的学习课件与测验。

### 1.2 核心能力

| 能力 | 说明 |
|------|------|
| **多角色档案** | 多子女数据隔离（错题/课件/测验/统计各自独立）|
| **拍题录入 OCR** | 支持多图串行上传、四层提取协议（原题/批注/订正/掌握状态）|
| **教材管理** | 分片上传（5MB/片）、AI 自动提取元数据和目录、封面截图 |
| **AI 课件生成** | 选择章节 → 豆包生成结构化课件（含讲解词）→ TTS 全文朗读 |
| **AI 测验出题** | 基于课件章节 / 错题本生成配套测验，豆包自动批改 |
| **错题专项讲解** | 针对单道错题，生成对应讲解课件 + 巩固测验 |
| **成绩看板** | 今日/本周收录、掌握率、7天趋势折线图 |

### 1.3 目标用户

- 中小学生家庭（K12 阶段）
- 使用场景：错题归档 → 章节学习 → 配套测验 → 历史回顾

## 2. 导航结构

应用采用三层 Hash 路由，共有 **3 个顶级 Tab**：

```
Dashboard（概览）
Resources（学习资料）
  ├─ 我的书架   (#resources/library)
  ├─ 错题本     (#resources/capture)
  └─ 学习小助手 (#resources/workshop)
AI课堂（Tutor）
  ├─ 课程学习   (#tutor/courseware)
  ├─ 错题讲解   (#tutor/wrong)
  └─ 历史记录   (#tutor/history)
```

> 顶部导航栏（桌面端）/ 底部 TabBar（移动端）显示 Dashboard / Resources / AI课堂 三个入口。用户档案和用户切换通过右上角的头像菜单操作。

## 3. 功能模块详解

### 3.1 Dashboard（概览面板）

启动后的默认首页，展示当前用户的学习概况。

| 组件 | 内容 |
|------|------|
| 统计卡片 × 4 | 今日收录 / 本周收录 / 待复习错题数 / 掌握率 |
| 趋势折线图 | 最近 7 天每日收录数量 |
| 最近时间轴 | 最近 5 条拍题/归档记录 |
| 快捷入口 | 4 个常用功能直跳链接 |

**掌握率计算**：`CORRECT / (CORRECT + WRONG) × 100%`
- ≥ 80%：绿色
- 60% ~ 79%：黄色
- < 60%：红色

---

### 3.2 Resources / 我的书架（LibraryHub）

管理已上传的电子教材（PDF / EPUB / TXT）。

**上传流程**：
1. 拖拽或点击选择文件（最大 100MB）
2. 文件 > 5MB 自动分片上传（每片 5MB，指数退避重试）
3. 后端解析文件内容，调用豆包提取元数据
4. 前端弹出元数据编辑表单，用户可修正 AI 提取结果
5. 确认后保存，PDF 自动生成封面截图

**AI 自动提取字段**：标题、学科、年级、类型、出版社、出版时间、标签、章节目录（树形）

**主要操作**：
- 卡片列表展示（封面 + 基本信息）
- 点击卡片 → 阅读器（Markdown 全文 / 目录树导航）
- 编辑元数据
- 删除（同时删除原始文件）

---

### 3.3 Resources / 错题本（CaptureModule）

上传试卷/作业图片，AI 自动识别并归档错题。

**两个子 Tab**：
- **错题**：展示 status=WRONG 的题目（待复习）
- **归档文件**：展示所有已处理的拍题记录

**上传流程（异步 OCR）**：
```
上传图片（支持多图同时选择）
    ↓
逐张串行发送 POST /api/analyze → 返回 taskId
    ↓
前端每 3 秒轮询 /api/analyze-task/:taskId
    ↓
OCR 完成 → 前端展示审核界面
    ↓
用户确认/修改题目状态（CORRECT/WRONG/CORRECTED）
    ↓
POST /api/save-scanned-item → 持久化入库
    ↓
庆祝动画（Canvas Confetti）
```

**四层 OCR 解构协议**：
```
第1层：印刷原题（题目本身）
第2层：红笔批改（教师批注）
第3层：学生行动（学生答案 / 订正内容）
第4层：收尾闭环（是否真正掌握）
```

**多页试卷**：一次选择多张图片时，系统串行处理并按选择顺序关联 `parentExamId` / `pageNumber` / `totalPages`，支持跨页试卷分组。

---

### 3.4 Resources / 学习小助手（StudyRoom）

根据书架中的教材和错题本，AI 生成课件和测验，产物保存到「AI课堂」。

**操作流程**：
1. **选择章节**：从我的书架选择教材 → 树形目录选择具体章节
2. **生成课件**：选择教学风格（严谨讲解 / 故事化 / 实践导向 / 探究式）→ 豆包生成结构化 Markdown 课件
3. **生成测验**：基于上一步课件内容，豆包生成配套测验题（选择/填空/解答）

> 生成的课件和测验自动保存到数据库，可在「AI课堂 → 课程学习」中查看。

---

### 3.5 AI课堂 / 课程学习（courseware Tab）

展示从「学习小助手」生成的章节课件和配套测验，按书名+章节分组。

**课件阅读模式**：
- 分节卡片展示（每节：标题 + 正文 + 可展开的"故事讲解"）
- **TTS 全文连播**：点击播放，豆包 TTS 分段（每段 ≤280 字）串行合成音频播放；支持暂停/继续/停止；豆包失败时自动回退到浏览器 Web Speech API
- 连播成功后自动标记「已学」（`lastStudiedAt`）

**测验模式**：
- 题目逐题展示（选择 / 填空 / 解答）
- 答完提交 → 豆包后台批改 → 结果保存到 `quiz_results`（原 quiz 条目从 `classroom_items` 删除）
- **二次批改**：用户可在历史记录中对每道题手动标记「正确/错误」，覆盖 AI 判分

---

### 3.6 AI课堂 / 错题讲解（wrong Tab）

针对错题本中的单道错题，AI 一键生成**专项讲解课件 + 巩固测验**。

入口：在「错题本」中点击某道题的「AI讲解」按钮，后端自动：
1. 生成该题的讲解课件（`source=wrong_problem`）
2. 生成对应的巩固测验

生成的条目在「错题讲解」Tab 中按错题来源分组展示，操作方式与「课程学习」一致。

---

### 3.7 AI课堂 / 历史记录（history Tab）

展示所有已完成测验的归档结果。

| 字段 | 说明 |
|------|------|
| 书名 + 章节 | 测验对应来源 |
| 得分 | `correctCount / total`（正确题数 / 总题数）|
| 得分率 | 百分比 |
| AI 学习建议 | 豆包批改后附带的个性化建议 |
| 批改时间 | 后台批改完成时间 |

点击记录可查看**题目详情**（每题：题干 / 学生答案 / 正确答案 / AI 解析），并支持二次批改。

---

### 3.8 用户管理（ProfilePage）

通过右上角头像菜单进入：

- **切换用户**：在已有用户间切换，数据按 `ownerId` 隔离
- **新建用户**：填写姓名、头像、出生年月（或直接指定年级）
- **编辑资料**：修改姓名、头像、出生年月 / 基准年级
- **删除用户**：不能删除当前正在使用的用户

> 用户数据持久化在服务端 SQLite `users` 表，不依赖 localStorage（localStorage 仅缓存"最后使用的用户 ID"）。

**年级推算逻辑**（后端）：根据 `birthDate`（出生年月）和当前日期自动推算中文年级字符串；用户也可通过 `baseGrade`（1~12）手动覆写。

## 4. 核心业务流程

### 4.1 教材上传（完整路径）

```
用户选择 PDF/EPUB/TXT 文件
    ↓ 文件 > 5MB → 分片上传（POST /api/upload-chunk × N，再 merge）
    ↓ 文件 ≤ 5MB → 直接 POST /api/upload-book
    ↓
后端解析（pdf-parse / epub2）提取文本
    ↓
判断：有可提取文本 → 豆包文本模型分析元数据 + 章节目录
     无文本（扫描版）→ pdftoppm 转图片 → 豆包视觉模型分析
    ↓
后端保存原始文件到 /opt/twinkle/data/originals/books/
后端生成封面截图  到 /opt/twinkle/data/obsidian/covers/
    ↓
前端展示元数据编辑界面 → 用户确认
    ↓
POST /api/save-book → 写入 books 表
```

### 4.2 拍题归档（完整路径）

```
用户上传图片（可多张）
    ↓ 逐张串行
POST /api/analyze → { taskId }
    ↓ 前端轮询
GET /api/analyze-task/:taskId（每 3 秒）
    ↓ 豆包视觉模型 OCR（耗时 30~450 秒）
status: done → 返回结构化 Markdown + 题目数组
    ↓ 前端展示审核界面
用户确认/修改题目状态（CORRECT / WRONG / CORRECTED）
    ↓
POST /api/save-scanned-item → 写入 scanned_items 表
    ↓ 庆祝动画
```

### 4.3 AI课堂学习（完整路径）

```
Resources/学习小助手 → 选择章节 → 选择教学风格
    ↓
POST /api/generate-courseware → 豆包生成结构化课件 → 写入 classroom_items(type=courseware)
    ↓（可选）
POST /api/generate-assessment → 豆包生成测验题 → 写入 classroom_items(type=quiz)
    ↓
AI课堂/课程学习 → 按书名+章节分组展示

用户点击课件 → 课件阅读（分节卡片 + TTS 朗读）
    ↓ 连播成功
POST /api/classroom/:id/mark-studied → 标记已学

用户点击测验 → 逐题作答 → 提交
    ↓
POST /api/quiz-results（QuizExam 组件提交）
豆包后台批改 → 写入 quiz_results
classroom_items 中对应 quiz 条目删除
    ↓
AI课堂/历史记录 → 展示批改结果
```

## 5. 使用技巧

### 5.1 多用户管理

- 每个子女拥有独立的错题本、课件、测验、统计数据
- 右上角头像菜单一键切换；切换时显示 Toast 提示
- 图书馆（教材）可设置 `ownerId=shared`，全家共享

### 5.2 高效拍题

- 手机相册多选模式，一次选多张试卷图片
- 系统串行处理，稳定性优于并发，不易触发 API 限流
- OCR 后建议仔细审核题目状态，修正有助于提高掌握率统计准确性

### 5.3 TTS 朗读技巧

- 网络不稳定时 TTS 可能出现加载延迟；失败会自动回退到浏览器朗读
- 切换页面（离开课件）时会自动停止朗读
- 建议在 Wi-Fi 环境下使用，豆包 TTS 音质优于浏览器内置

### 5.4 测验二次批改

AI 对解答题的判分仅供参考，尤其主观题可能不准确。在历史记录的题目详情中，可点击「✓ 标为正确」或「✗ 标为错误」手动修正，分数会实时重算。

### 5.5 备份数据

所有数据均在 `/opt/twinkle/data/`，建议定期备份：
```bash
tar czf twinkle-backup-$(date +%F).tar.gz -C /opt/twinkle data
```
