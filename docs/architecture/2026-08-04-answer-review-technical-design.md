# 作答回顾：技术设计（Gate 4）

## 1. 背景

评分服务将不再是作答提交链路的一部分。作答记录需要保存足够的不可变题目快照，才能在题库或课堂任务变化后仍能回顾。

## 2. 目标

以一个小的“回顾快照 + 主动标记”模型取代两套评分结果模型，同时可受控清除历史评分数据。

## 3. 方案

### 3.1 数据边界

| 数据 | 保留/新增 | 删除/停止读取 |
| --- | --- | --- |
| 作答 ID、ownerId、资料/试卷引用、提交时间、学生答案 | 保留 | - |
| 每题题目、参考答案、解析、题型 | 保存/保留为回顾快照 | - |
| `needsReinforcement` | 新增或由专属关联表保存 | - |
| `correctCount`、`percentage`、`diagnosticScore`、`suggestions`、`gradedAt`、`isCorrect`、量规、证据、置信度、评分结论、改判事件 | - | 删除/停止读取 |

课堂需巩固标记使用独立、按 `attempt/result + questionId + ownerId` 唯一的记录；统一错题本只查询该记录，不再从任何“自动判错”字段推导。

### 3.2 提交流程

```text
客户端答案 + 题目快照
  -> 校验 ownerId、题目归属、答案题号
  -> 原子写入 submitted attempt/result + review snapshot
  -> 返回回顾 ID
  -> 客户端读取回顾详情
```

该流程不得导入 `OpenAI`、调用 `gradingService` 或调度异步评分。

### 3.3 清理与回滚

- 新增仅评分数据清理 CLI，默认 dry-run；生成 SQLite 备份、manifest、保留计数与文件哈希。
- `--apply --manifest` 重新比对待删集合与保留集；不一致或缺少可回顾的必需保留字段时停止，无写入。
- apply 在单个 SQLite 事务内删除评分专属表行/字段值和旧自动错题派生引用；保留回顾快照与主动需巩固标记。
- 生产 apply 需要停服务、人工审核 manifest 和单次明确授权；回滚只能从本次 SQLite 备份恢复。

### 3.4 影响与兼容

- 删除评分路由和模型依赖后，旧评分 API 返回稳定的 `410 grading_retired`，不暴露旧数据。
- 看板 API 不再计算 `masteryRate` 或 `trendBySubject`；前端同步移除消费。
- 历史 `quiz_results` 的题目快照可转换为回顾项目；无法恢复完整题目/答案/参考答案/解析的记录只返回稳定不可回顾状态，不能回退显示分数。

## 4. 风险

- 历史数据模式复杂，迁移前必须在真实结构的副本上验证；不允许用宽泛 SQL 猜测列存在。
- 需巩固与现有错题讲解关联必须有明确来源类型，避免污染上传错题表。
