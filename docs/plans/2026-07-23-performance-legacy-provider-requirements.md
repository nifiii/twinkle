# 性能与旧提供商清理需求契约

状态：Gate 1 已确认

## 1. 背景

生产站点 `https://dd.haokuai.uk` 的图书 PDF 解析、试卷 OCR 和课件生成响应过慢。旧提供商残留仍存在于图书元数据和实时导师实现中。

## 2. 目标

- 在用户端端到端口径下缩短核心异步流程等待时间。
- 移除全部旧提供商运行时依赖，同时保留 LiveTutor 的实时语音输入和流式语音回复。
- 支持最多 10 个资源密集型任务进入系统；性能承诺覆盖其中同时运行的前 3 个任务，其余任务排队。

## 3. 方案

### 3.1 统一术语

| 术语 | 定义 |
| --- | --- |
| 端到端耗时 | 用户点击上传或生成开始，到页面显示可用结果的总时间；包括上传、排队、解析、模型调用、保存和页面展示。 |
| 资源密集型任务 | 试卷 OCR、PDF 图书解析、课件生成。 |
| 并发运行 | 已被调度并实际占用解析、模型或计算资源的任务数量，不包含排队任务。 |
| 排队 | 第 4 至第 10 个资源密集型任务已被系统接收，但未开始重资源处理；页面必须展示排队状态。 |
| 旧提供商清理 | 不再保留旧 SDK、环境变量、调用路径、类型值、前端标识或相关文档声明。 |

### 3.2 业务规则

| ID | 规则 |
| --- | --- |
| BR-001 | 在最多 3 个资源密集型任务并发运行时，试卷从图像提交到结构化题目结果可保存为错题或试卷的端到端耗时不超过 60 秒。 |
| BR-002 | 在最多 3 个资源密集型任务并发运行时，课件生成的端到端耗时不超过 60 秒。 |
| BR-003 | 在最多 3 个资源密集型任务并发运行时，约 54.2 MiB 的 `tiyu_origin.pdf` 端到端解析耗时不超过 180 秒。 |
| BR-004 | 系统最多接收 10 个资源密集型任务；第 4 至第 10 个任务允许排队，且必须在前端展示排队状态。 |
| BR-005 | 旧提供商清理后，LiveTutor 必须保留实时麦克风输入和流式语音回复，不得退化为纯文字问答。 |
| BR-006 | 旧提供商清理不得降低图书元数据提取、图书上传、OCR、课件和测验的既有可用性。 |
| BR-007 | LiveTutor 从用户停止说话到开始播放导师第一段语音的 P95 不超过 3 秒。 |
| BR-008 | LiveTutor 使用豆包的实时双向语音服务，允许产生相应外部 API 成本。 |
| BR-009 | OCR 可以压缩非必要的全文描述，但结果必须保留可独立保存为错题或试卷的结构化题目：题号、自包含题干、学生答案、标准答案、批注、知识点和状态。 |

### 3.3 验收样本与度量

| 场景 | 固定样本 | 目标 |
| --- | --- | --- |
| 试卷 OCR | `162157_dadf07c1.jpg`，300,776 B | 60 秒 |
| PDF 图书解析 | `tiyu_origin.pdf`，56,866,009 B | 180 秒 |
| 课件生成 | 先解析 `tiyu_origin.pdf`，取解析目录第一章；使用本次 OCR 的 9 道题作为固定错题上下文，`teachingStyle=rigorous` | 60 秒 |

每个场景在 3 并发下连续运行 5 次，端到端耗时 P95 必须不高于相应目标。

### 3.4 当前事实

- `LiveTutor` 曾通过浏览器直接使用旧实时音频模型。
- 图书元数据和文件名推断曾存在旧调用路径。
- 现有项目配置已使用豆包文本、视觉 OCR 和 TTS 服务；替代方案必须基于实际能力与延迟基线确认，不可假定接口等价。

## 4. 风险

- 3 并发下的 60 秒 OCR 与课件目标可能受上游模型首包延迟、模型限流和网络带宽限制。
- PDF 的大小、页数、是否扫描件和图片分辨率都会显著影响耗时；当前验收只对指定样本做出承诺。
- LiveTutor 的实时音频替代是外部服务与协议迁移，涉及成本、兼容性和用户感知延迟，不能当作普通依赖删除。
- 仅提升并发会放大内存、CPU、磁盘和上游 API 限流风险，必须通过队列与可观测性控制。

## 5. 回滚

- 性能优化发布必须支持关闭新调度策略或回退到当前同步/异步路径。
- 旧提供商清理应在等价替代链路经验证后切换；发布前保留可回滚版本和环境变量配置，但不得在新版本继续暴露供应商密钥给浏览器。
- 生产切换前须完成数据库、上传文件和任务状态的兼容性检查，禁止破坏已有任务记录。

## 6. FAQ

### 为什么 SLO 只覆盖 3 并发？

这是已确认的用户体验承诺边界。系统仍可接收 10 个任务，但第 4 至第 10 个任务应排队并明确反馈状态，避免无控制并发导致所有任务同时超时。

### 为什么不能直接删除旧 SDK？

因为 LiveTutor 和图书元数据可能仍有调用链依赖。直接删除会造成实时语音导师或图书上传元数据能力中断。
