# 当前年级保存与试卷分类修复

## 1. 背景

偏差分类：两项均为代码实现 bug（第 7 类）。当前年级保存未重新锚定学年；明确标记为“考试真题”的资料被分类规则漏识别。回到用户资料保存任务，以及母卷任务 AC-SP-001/004/010 修正实现，无需改变已确认 PRD。

## 2. 目标

- 手动指定的是当前年级，显式保存相同数字也生效；刷新一致，后续仍每年 9 月升级。
- 明确标记的试卷进入母卷候选，从教材候选排除；奥数继续独立分类。不根据标题猜测来源。
- 不改变原始资料，不自动修改生产学生档案，不放行缺图或不支持的图画作答。

## 3. 方案

保留 React + Express + SQLite。资料表单 → PATCH users → SQLite 年级/锚点 → GET users → 当前学生档案；教材和母卷列表复用现有分类函数，不引入迁移或缓存兜底。

### FIX-001 用户资料保存

- Outcome：学生当前年级可保存、刷新和用于后续出题。
- Inputs：现有“手动指定当前年级 / 每年 9 月升级”规则；AC-SP-004。
- Scope：ProfilePage、App 保存回调、userService、users 路由和隔离 API 测试。
- Non-goals：不批量重设现有学生，不修改历史测试的年级快照。
- Acceptance：旧基准 4/2026-07 在 2026-10 显示 5，PATCH 4 后 GET 显示 4；省略 baseGrade 不改锚点；null 清除手动模式；拒绝非 1–12 整数；中国时间 9 月边界在 UTC 和上海宿主上一致。表单默认当前有效年级；保存中禁重复提交，失败保留编辑，成功才退出。
- Freedom：日期计算与本地交互内部实现自行选择，保持 API 响应形状和年度升级规则。
- Dependencies：无。

PATCH 契约补充：baseGrade 省略表示不修改；1–12 整数表示重新锚定当前年级；null 表示清除 baseGrade 和 baseGradeSetAt，改用出生日期。birthDate=null 清除出生日期。非法年级返回 400。POST 使用相同年级校验；日期锚点采用 Asia/Shanghai 的 YYYY-MM。

### FIX-002 明确试卷标记识别

- Outcome：考试真题、期中/期末测试及真题均正确进入母卷模式。
- Inputs：母卷 PRD 的已知分类/标签规则；AC-SP-001/010。
- Scope：共享 materialClassification 函数、分类及真实候选服务测试。
- Non-goals：不靠标题猜分类，不复制/重解析/删除源卷，不改变归属。
- Acceptance：生产样本中的四份明确试卷分类均识别；奥数/数学竞赛仍排除；教材与非法标签不误判；API 候选包含对应记录，教材服务拒绝它们。
- Freedom：正则或明确标记集合自行选择，前后端必须使用同一判断。
- Dependencies：FIX-001 验收后交付。

### 图片题后续支持边界

当前只支持文字试卷。需要先核对原 PDF 页图与解析正文，区分原卷缺材料和解析丢图。完整图题支持须另行确认页图提取/视觉解析、图与题绑定、原创图题生成、网页作答及 A4 输出契约。已有 PRD 允许源卷年级不同并按学生年级适配；年级不同本身不应视为材料缺失，但实际超纲或无法适配仍应阻断。本轮不扩大图题能力，不把原 PDF 尚未核验的情况说成已确认缺页。

## 4. 风险

分类函数同时影响前后端候选及后端来源校验，必须联测；日期时区影响升学边界，不能依赖 Docker 本地时区。已有历史锚点保留，部署后用户需要重新保存当前年级。本轮无数据库结构变更；回滚代码即可，已显式保存的档案按正常用户变更保留。生产尚未部署时不得声称生产验收通过。
