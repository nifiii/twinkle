## 1. 背景

### 1.2 关键问题
1. **职能重叠严重**
   - "智慧工坊（生产）"和"AI 课堂（消费）"是同一条用户旅程被强行切成两块：用户必须先去工坊"生成"，再切到 AI 课堂"使用"，**多一次心智跳转**。
   - "拍题"内嵌了 `KnowledgeHub`，变成"拍题 + 错题库 + 归档库"三合一，子 Tab 三个，**模块边界模糊**。
   - "智能考场（ExamCenter）"功能与"智慧工坊→测验"、"AI 课堂→错题测验"高度重复，且未联通后端，属于历史遗留。

2. **按钮过载**
   - `StudyRoom` 顶部一行有"教材模式 / 错题模式"切换 2 颗 + "选择章节 / 生成课件 / 配套测验"3 颗步骤按钮，加上模式标题就堆了 5+ 颗按钮。
   - `Dashboard` 4 张统计卡都跳转到 `tutor` 不同子路径，但 `tutor` 内还要再选 Tab，**双层导航**。
   - `LibraryHub` 顶部搜索 + 3 个独立下拉筛选 + 上传按钮共 5 个控件挤一行，移动端会折行混乱。

3. **风格不统一**
   - 圆角：项目里 `rounded-lg(173) / rounded-xl(35) / rounded-2xl(21) / rounded-3xl(12) / rounded-full(76)` 五档同时使用，**没有统一节奏**。
   - 颜色：sky / mint / sunset / neon-blue / neon-purple / neon-pink / 学科色 (math/chinese/english/science) 七套色板并行，每个页面挑选不同主色（图书馆紫、AI 课堂粉、工坊蓝绿、考场紫...），**视觉跳跃**。
   - 文案语气：「闪闪」「智能考场」「智慧工坊」「AI 课堂」「学习记录 / 在线学习课堂」并存，**严肃冷酷与活泼可爱风格混杂**。

4. **用户路径不清晰**
   - 家长："今天孩子学了啥？" → 只能在 Dashboard 4 张卡 + 3 个列表里翻，缺少"家长视角周报"。
   - 孩子："今天我要学什么？" → 必须自己理解"工坊→课堂"的流转，不符合"即开即用"。

### 1.3 用户画像与典型动作
| 角色 | 高频动作 | 当前路径 | 痛点 |
|---|---|---|---|
| 孩子 | 上一个错题被讲解 → 做配套测验 | 工坊→选错题→生成讲解→生成测验→去 AI 课堂找列表→点开→做 | **5 次跳转** |
| 孩子 | 看今天要学什么 | Dashboard 4 张卡 + 翻 3 个列表 | 信息密度高、不够"任务卡" |
| 家长 | 把试卷拍下来归档 | 拍题→等 OCR→编辑→保存 → 切到错题列表查看 | OK，但拍题与列表分两个子 Tab |
| 家长 | 上传新教材 → 立即给孩子布置一节课 | 图书馆→上传→编辑元数据→保存→切到工坊→选书选章→生成课件→切到 AI 课堂找 | **跨 3 个 Tab** |

---

## 2. 目标

1. **导航减半**：顶级 Tab 从 5 收敛到 3（保留扩展位 1 个）；任何核心动作 ≤ 3 次点击可达。
2. **角色驱动**：默认进入"今日"页（孩子视角），家长有快速切换入口。
3. **统一风格**：1 套色板 + 1 套圆角阶梯 + 1 套字号阶梯 + 1 套阴影/插画；面向 6–14 岁儿童 + 家长，"活泼但不幼稚"。
4. **PC / 移动端同源**：响应式 + 侧栏折叠为底部 Tab Bar；卡片组件在两端通用。
5. **不破坏后端**：所有改动聚焦前端 IA 与组件，**保持 `services/apiService.ts` 与 `/api/*` 不变**。

## 3. 方案

### 3.1 信息架构（IA）重组

#### 3.1.1 目标导航树

```
┌────────────────────────────────────────────────┐
│ 闪闪                                           │
├────────────────────────────────────────────────┤
│ 1. 今日（首页）           home          🏠      │  ← 合并原 Dashboard + AI 课堂入口

│    ├─ 待完成测验                                │
│    └─ 学情趋势 + 周报入口                       │
│                                                │
│ 2. 学习                  learn         🎓      │  ← 合并 智慧工坊 + AI 课堂 (生产+消费一体)
│    ├─ 教材模式（选教材→课件→测验，一体三步）    │
│    └─ 错题模式（选错题→讲解→测验，一体三步）    │
│    ─ 任意已生成内容直接列在右侧轨道，可点开继续 │
│                                                │
│ 3. 资料                  library       📚      │  ← 合并 图书馆 + 拍题 + 归档
│    ├─ 教材（原 LibraryHub）                     │

│    └─ 归档（试卷/笔记，原 archived_docs）      │

│                                                │
│ (4). 设置（用户、家长视图、提醒）  settings ⚙️  │  ← 折叠到右上角头像菜单，不占主导航
```

**砍掉**：
- `tutor` Tab（融入 `learn`）
- `study_room` Tab（融入 `learn`）
- `capture` Tab（融入 `library`，"拍题"变成 `library` 内部"+ 新增 → 拍照"）
- `exams` Tab（已废弃，确认无后端依赖后删除）

**保留路由兼容**：原 `#tutor/courseware/<id>`、`#tutor/wrong/<id>` 等深链 → `App.tsx` 内做一次 hash 重写到新路径 `#learn/courseware/<id>`，不破坏 Dashboard 卡片跳转与外部链接。

#### 3.1.2 改动前/后对比

| 用户旅程 | 改动前 | 改动后 |
|---|---|---|
| 上传教材 → 生成课件 → 学习 | 图书馆→上传→编辑→保存 → 工坊→选教材→章节→生成课件 → AI 课堂→找列表→点开 | 资料→上传→（自动跳）学习页教材轨道→选章节→一键生成→当页学习 |
| 错题→讲解→测验 | 拍题（识别）→等→工坊→错题模式→选题→生成讲解→生成测验→AI 课堂→找→做 | 资料/今日→错题卡→「订正」→学习页错题轨道→自动生成→当页做 |
| 看今日学习 | Dashboard 4 卡 + 3 列表 | 今日页：上半屏"今日 3 个任务"卡片，下半屏趋势 + 待办 |
| 切换孩子视角 | 顶部 UserSwitcher | 顶部 UserSwitcher（保留） |

### 3.3 UI 设计语言（统一）

#### 3.3.1 设计基调
**关键词**：温暖 / 圆润 / 柔光 / 学科彩点缀 / 不幼稚
- 灵感参考：Notion + 多邻国 + 小猿口算 的中间地带。
- 既适合孩子（卡片有插画、状态有动效），也让家长看着不刺眼（主体白底 + 灰阶 + 1 个主色）。

#### 3.3.2 设计令牌（Design Tokens）

```ts
// tailwind.config.js extension（不改老 token，新增 brand-* 命名空间统一引用）
```

**圆角阶梯**（从 5 档收敛到 3 档）：
- `rounded-md` (8px)：表单元素、Badge
- `rounded-2xl` (16px)：卡片、按钮、Modal（主用）
- `rounded-full`：头像、Pill 标签

**阴影阶梯**（从 5 档收敛到 3 档）：
- `shadow-soft`: `0 2px 8px rgba(31,41,55,0.06)`：默认卡片
- `shadow-pop`: `0 8px 24px rgba(31,41,55,0.10)`：悬浮 / 弹窗
- `shadow-focus`: `0 0 0 4px rgba(61,142,230,0.15)`：聚焦态

**字号阶梯**（中文友好，移动端基准）：
- 显示标题 `text-2xl` 24/32（首页欢迎条）
- 段落标题 `text-lg` 18/26
- 主文 `text-base` 16/24
- 辅助文 `text-sm` 14/22
- 标签 `text-xs` 12/18

**字体**：保持 `Inter + 苹方/微软雅黑` 回退链不变。可选添加圆体中文 `MiSans / Source Han Rounded` 提升活泼感（需用户确认是否引入字体文件）。

**插画风格**：
- 空状态：Storyset / unDraw 同色系 SVG（不用 emoji 大图标当主插画）。
- 学科图标：用统一线条粗细的 lucide-react 图标 + 学科色 12% 透明度底（参考现有 Dashboard 卡片）。

#### 3.3.4 PC / 移动端适配策略

| 断点 | 行为 |

## 4. 风险

| 风险 | 等级 | 说明 | 缓解 |
|---|---|---|---|
| 老深链失效 | 中 | Dashboard 卡片硬编码 `tutor/courseware/...` | App.tsx 加 hash 重写中间层，保留 6 个月再清理 |
| 后端 API 假设 | 低 | 本方案只动前端 IA，未触碰 `services/*` 与 `/api/*` | 先做"导航重组 + 风格重做"，后做"组件下沉" |
| 工坊+课堂合并的状态管理复杂度上升 | 中 | 列表与表单同屏，state 管理需要重构 | 抽到 `useLearnState` 自定义 hook，分 textbook / wrong 两种 reducer |
| 设计令牌全量替换风险 | 高 | 一次性改 tailwind.config.js 会触发 384 处样式 | 分阶段：① 新增 `brand-*` 命名空间并行 → ② 各组件迁移 → ③ 老 token deprecated 并删除 |

## 7. FAQ

**Q1：为什么不保留"智能考场"？**
A：`ExamCenter.tsx` 当前调用的是 `geminiService.generateAssessment` 直出 markdown 字符串，没有题目结构、没有判分、没有归档。"智慧工坊→测验"已包含完整能力，且接通 `/api/quizzes`。保留只会让用户混淆。

**Q2：为什么把"工坊"和"AI 课堂"合并成"学习"？**
A：核心心智是"学一节课"，不是"先生产再消费"。生产侧（生成）和消费侧（学习/做题）应该共面同屏，左侧管理已生成内容、右侧操作当前学习对象，这是 Notion / Linear / Figma 通用范式。

**Q3：为什么"拍题"被收进"资料"？**
A："拍题"的本质是**输入资料的方式之一**（其他方式是"上传图片/PDF/教材"）。现有 IA 把"输入方式"当顶级 Tab，等于把"打字键盘"做成 Tab。改造后所有"添加资料"都收口到 FAB。

**Q4：家长视角和孩子视角要不要拆？**
A：v1 不拆。家长通过顶部 UserSwitcher 切换到孩子身份即可看到对应数据。v2 可在"今日页"加家长开关，展示周报视图。

**Q5：是否需要重写所有 1100 行的 AI 课堂？**
A：不需要。v1 不动 AIClassroom 的内部实现（章节分组、二次批改等），只把它作为"学习页右侧工作区"嵌入。这是 KISS。

**Q6：移动端 3 Tab 是不是太少？**
A：3 Tab + FAB + 头像菜单 = 5 个一级入口，对移动端是恰当密度。现在 5 Tab 在 360px 屏幕上每个 Tab 只有 72px 宽度，文字+图标已贴边。
