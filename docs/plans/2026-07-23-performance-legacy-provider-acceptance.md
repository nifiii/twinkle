# 性能与旧提供商清理验收测试

状态：Gate 3 已确认

## 1. 背景

本文件将已确认的业务规则转为可自动或手工复核的行为测试，避免只验证单次请求或后端局部耗时。

## 2. 目标

在发布前证明端到端性能、排队体验、功能保持和旧提供商清理都满足已确认范围。

## 3. 方案

### 3.1 验收测试

| ID | 场景 | 验收条件 |
| --- | --- | --- |
| AC-001 | OCR 性能 | 给定 `162157_dadf07c1.jpg`，当 3 个资源密集任务同时运行时，连续 5 次从图像提交到结构化题目可保存为错题或试卷的 P95 不超过 60 秒；每题必须含题号、自包含题干、学生答案、标准答案、批注、知识点和状态。 |
| AC-002 | PDF 性能 | 给定 `tiyu_origin.pdf`，当 3 个资源密集任务同时运行时，连续 5 次从点击上传到图书可用的 P95 不超过 180 秒。 |
| AC-003 | 课件性能 | 先解析 `tiyu_origin.pdf` 并取解析目录第一章，以本次 OCR 的 9 道题为固定错题上下文、`teachingStyle=rigorous` 生成课件；当 3 个资源密集任务同时运行时，连续 5 次从点击生成到已保存且可打开的核心课件 P95 不超过 60 秒。核心课件固定为 5 节：导入、3 个关键知识节和小结；每节正文为 120-180 个中文字符。扩展讲解、例子和讲稿异步补全，不计入该 60 秒门禁，且失败不得影响核心课件可读。 |
| AC-004 | 队列保护 | 当已运行 3 个资源密集任务后再提交 7 个任务时，后续任务持久化为排队状态，前端可见排队提示，且不丢失、不重复执行。 |
| AC-005 | 任务恢复 | 当用户在排队或处理时刷新页面后，返回相应页面可恢复任务状态；任务完成后显示可用结果。 |
| AC-006 | 失败重试 | 当模型调用、转图或保存失败时，页面展示可读错误，重试只执行失败阶段，不要求重新上传或重复生成已完成内容。 |
| AC-007 | 旧提供商清理 | 构建产物、前后端依赖、环境变量、运行时调用、类型与 UI 标识均不包含旧提供商残留；历史已有记录仍可在书架和列表中显示。 |
| AC-008 | LiveTutor 功能 | 给定已授权用户和可用麦克风，用户语音可被实时发送，导师语音和双方转写可流式返回，用户打断可停止待播音频。 |
| AC-009 | LiveTutor 时延 | 在目标网络和服务配额下，连续 5 次语音轮次的“用户停止说话至首段语音播放”P95 不超过 3 秒。 |
| AC-010 | 密钥隔离 | 浏览器构建产物、页面变量、网络请求和错误提示均不暴露供应商密钥；实时会话由后端创建和代理。 |

### 3.3 测试数据与计时规则

- OCR 样本：项目根目录 `162157_dadf07c1.jpg`。
- PDF 样本：项目根目录 `tiyu_origin.pdf`。
- 课件：先解析 `tiyu_origin.pdf` 并取解析目录第一章；书名和学科取该解析结果，学生固定为“性能验收学生”，`ownerId=benchmark`，讲解风格固定为 `rigorous`，错题上下文固定为本次 OCR 的 9 道结构化题目。5 次测试保持完全相同输入。
- 每次计时从用户点击上传或生成开始，至页面明确展示“结果可用”为止；课件以核心课件已保存、可打开为止，扩展状态另行记录。记录上传、排队、每个处理阶段与页面渲染耗时。
- P95 以 5 次样本排序后取最慢值，避免虚构统计精度。

### 3.4 原型决策

无需视觉原型。需要在实施第一任务中以受控测试或最小状态机验证以下问题：任务在刷新、进程重启和并发提交时是否保持唯一性与可恢复性。

## 4. 风险

- 固定 5 次的 P95 等于最慢一次，只适合发布前回归门禁，不替代长期生产 SLO 监控。
- LiveTutor 的实时音频测试需要真实豆包账户、麦克风权限和代表性网络条件，不能只依赖单元测试。

## 5. 回滚

每项验收失败都应阻止灰度扩大；可回退到上一镜像与旧任务路径。不得通过放宽计时起点或隐藏失败状态来“通过”验收。

## 6. FAQ

### 为什么要在 3 并发下测试？

这是已确认的性能承诺边界。只测单任务无法发现当前局部并发叠加导致的上游限流和资源争用。
