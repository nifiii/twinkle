# 背景

LiveTutor 的实时 ASR 会连续返回中间转写。原实现未传递 `is_interim`，前端将每个结果追加为消息，导致单句语音显示为多条重复气泡。现有会话仅支持 PCM 音频上行，缺少常规文字输入。

# 目标

1. 语音中间转写仅在当前用户气泡原位更新，最终转写只保存一条。
2. 提供移动端优先的常规聊天布局，同时支持文字输入和实时语音。
3. 保持现有 PCM 上行、流式音频播放、VAD 打断、会话限制与 `ownerId` 校验。

# 方案

```text
浏览器 PCM -> WebSocket 二进制 -> TaskRequest(200) -> 豆包实时会话
浏览器文字 -> WebSocket JSON -> ChatTextQuery(501) -> 豆包实时会话
ASR is_interim -> 当前气泡替换；ASR final -> 固化消息
ChatResponse 流 -> 同一导师气泡追加；TTS 流 -> 现有播放队列
```

后端只接受 `{ "type": "text", "text": "..." }`，去除空白并限制为 2000 个字符，避免任意 JSON 或超长正文占用会话资源。前端在 WebSocket 会话就绪前禁用发送，避免本地消息与上游状态不一致。

# 风险

- 实时服务需确认语音会话内的 `ChatTextQuery(501)` 可用。部署后先分别验证一次文字输入与语音输入。
- 当前家庭内网仍使用 `ownerId` 标识用户，不能作为公网鉴权方案。

# 回滚

回滚本次提交即可恢复旧语音面板和仅 PCM 上行路径；不会影响数据库或已有学习数据。

# FAQ

**为什么中间识别不保存？** 它会在用户未停顿前反复修正，只有最终 ASR 结果才是稳定内容。

**文字输入会关闭麦克风吗？** 不会。用户可用语音按钮临时暂停音频上行，文字和语音共用同一个导师会话。
